# Neko Info 轻量桌面版设计

日期：2026-11-01

状态：用户已确认书面设计，首版代码已实现并通过独立设计与代码复核；Linux 发行包和桌面会话验证待执行。

## 目标与定位

Neko Info 是一个轻量、原生的 Linux 桌面状态挂件。用户在编译、浏览或视频通话时，可以快速查看 CPU、内存和网络的当前状态与短时变化。

首版支持 Debian 和 Arch Linux，在 GNOME 与 KDE 的普通桌面会话中作为紧凑窗口运行。保留猫咪符号与小体积，优先保证可读性、采样准确性和低开销。

## 已确认的范围

- 使用 Python、psutil 和 GTK4 原生界面。
- 移除 WebKit、临时 HTML 和文件监控刷新链路。
- 默认每两秒采样，展示最近一分钟趋势。
- 默认展示 CPU、内存和网络；每核 CPU 详情按需展开。
- 同一份源码提供 Debian 打包配置与 Arch PKGBUILD。
- 普通用户权限运行，依赖交由发行版包管理器安装。
- 普通紧凑窗口是基础模式，桌面固定模式后续单独评估。

首版不包含完整进程管理、GPU、温度、磁盘、电池、远程监控、插件系统、云端服务或持续动画。没有用户数据上传。

## 界面与交互

使用一个可移动、可关闭的普通窗口，遵循桌面环境提供的窗口管理行为。首版不承诺置底、跨工作区显示、任意绝对定位或隐藏任务栏条目。

概览按 CPU、内存、网络的顺序排列，每项都有明确标签、当前值和短时趋势。默认内容不随 CPU 核心数量增长。CPU 展开区采用可滚动布局展示每个逻辑处理器，收起后恢复紧凑概览。

内存同时显示占用比例、已用/总量与可用量。已用量采用 total - available 的展示口径，并在说明中明确：可用量包含系统可回收的部分缓存，不等同于完全空闲内存。交换分区不在首版概览内。

网络显示上下行速率，单位明确为 KiB/s 或 MiB/s。首版聚合 psutil 提供的非 loopback 网络接口计数；说明 VPN、桥接与虚拟接口可能导致重复统计，不把该值宣传为精确的互联网带宽。接口选择留待后续需求验证。

曲线按实际时间展示最近 60 秒的数据；启动阶段只显示已有样本，不补造历史。上下行使用独立的曲线和文字标签。不能仅依赖颜色传达含义。

提供浅色与深色外观，并优先跟随系统偏好。GTK 4.20 之前通过已有 Gio 依赖异步读取和监听桌面 appearance portal；服务不可用时保留原生 GTK 主题，退出时取消请求并断开监听。首版使用稳定可读的背景，不要求半透明。猫咪作为静态品牌符号，不将单次高占用直接标记为故障。

## 数据与刷新

采样器、有限历史缓冲区和界面分别承担数据采集、趋势管理与显示职责。采样器无需导入 GTK，便于独立验证。

由 GTK 主循环维护唯一的定时采样源。CPU 采用非阻塞的区间统计；启动时先初始化基线，首个有效区间样本前显示等待状态。汇总 CPU 和每核 CPU 来自同一轮采样，汇总为各逻辑处理器占用率的平均值。

网络速率通过相邻计数器差值除以单调时钟的实际时间差计算，不能假定回调始终精确相隔两秒。接口新增、计数器下降或长时间休眠后重建基线，不显示负速率，也不把跨休眠区间连接成连续趋势。

每次采样只更新现有控件和曲线，不重建窗口。历史只保存在内存，按时间淘汰过期样本；不写采样日志，不持久化趋势。窗口关闭时移除定时器并正常退出，无额外后台服务。

## 错误与配置

某一指标读取失败时，该指标显示不可用，其他指标继续刷新；恢复后重新建立必要的基线。开发运行时可输出简短诊断到标准错误，不弹出周期性错误对话框。

首版不引入通用配置框架，不迁移旧版依赖 HTML 路径和绝对窗口坐标的配置。默认行为无需配置文件即可运行。需要保存用户偏好时，只保存明确提供的选项，使用 XDG 配置目录；无效配置回退到默认值。

开机启动为用户主动启用的选项，采用桌面会话的 XDG autostart 机制；不在安装脚本中默认启用，也不使用 root 服务或外部 daemon 命令维持运行。

## 源码与分发

保持单一 Python 源码包，区分应用入口、采样/历史和界面三种职责。旧版根目录脚本与安装树中的源码副本不再分别维护；安装内容由单一源码生成。

采用标准 Python 项目元数据与构建方式，构建、测试和安装命令在实施计划中具体化。发行包不捆绑 Python 解释器或浏览器引擎，不通过安装脚本执行 pip，也不修改系统 Python 环境。

Debian 提供可构建的 debian/ 配置，声明 Python、GI、GTK4 和 psutil 的发行版依赖。Arch 提供 PKGBUILD，使用同一发布源码与安装布局，并声明相应的发行版依赖。版本号、许可证、桌面入口与图标来源保持一致。保留现有 MIT 许可证与作者声明。

可执行入口放在发行包的标准系统路径；应用资源采用项目自身名称，不向 Adwaita 主题目录安装项目图标。安装、升级和卸载不依赖网络下载 Python 包。

提供 PKGBUILD 不等于已经发布到 AUR；提供 Debian 构建配置也不等于进入 Debian 官方仓库。对外发布属于后续独立步骤。

## 兼容边界

验证基线为实施时的 Debian stable 和 Arch Linux，以及 GNOME、KDE 的 Wayland 会话。记录确切测试版本；对 X11 的支持仅按实际验证结果声明。

两个发行版共享功能与数据口径。普通窗口模式不依赖桌面扩展或 Layer Shell。以后若增加桌面固定模式，应独立设计桌面集成，并保留普通窗口回退能力。

## 轻量化与验收

通过架构限制开销：单进程、单个采样定时器、默认两秒一次、有限内存历史、无持续动画、无浏览器引擎、无周期性文件写入。

性能数字必须来自 Linux 实测。记录测试硬件、显示缩放、发行版、桌面版本、空闲窗口状态、CPU 统计口径、RSS 和采样频率。首个 Linux 原型建立基线，再决定可执行的数字预算，不预先声称未经测量的开销。

验收检查：

1. Debian 构建环境能够生成并安装 .deb；Arch 的干净构建环境能够从 PKGBUILD 构建并安装。
2. 安装后能够通过应用菜单和命令启动，普通用户无需额外 pip 安装。
3. 在 GNOME 与 KDE 的目标会话中验证启动、移动、缩放、展开与关闭；未验证的组合明确标记。
4. 自动验证 CPU 初始化、内存口径、网络时间差计算、接口变化、计数器重置和历史淘汰。
5. 手动验证休眠恢复、网络断开与恢复、高核心数量布局、浅深色外观及高 DPI 可读性。
6. 连续运行 30 分钟检查历史缓冲有界、资源占用没有持续增长，并确认关闭后没有残留进程。
7. 开机启动默认关闭，启用和关闭后分别验证下一次桌面登录行为。
